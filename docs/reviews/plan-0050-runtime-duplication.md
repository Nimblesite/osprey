# Runtime duplication review

Reviewed 2026-11-04 for plan 0050. This records the C-family review that the Deslop gate cannot perform, including the resulting lifecycle fixes. The broader GPU failure-handling and final CI requirements remain open.

Deslop 0.38.0 scans 1,066 supported files and measures 6,816 duplicated lines out of 229,147 (2.9745%). Its explicit `compiler/runtime` scan discovers **zero supported source files**. Its empty result is an engine limitation, not evidence that the runtime is clean. The supported-source ceiling is tightened from 3.00% to 2.98%; no exclusion is added.

The separate inventory covers all 187 C, header, Objective-C and Metal files under `compiler/runtime`, including test harnesses. A local candidate pass compares windows of fourteen non-comment lines with identifiers and string literals normalized, retaining punctuation, operators and numeric constants. This is a lexical aid, not a C parser or a semantic equivalence proof. I manually compared its six initial candidate groups and separately reviewed the numeric conversion, matrix, allocation, transfer and resident-resource families. The final inventory contains 44,021 source lines and five retained candidate groups.

| Evidence | Decision |
| --- | --- |
| `system_runtime.c`, the two `await_process` definitions | Merge. Their signatures and complete statement-token sequences are identical. One definition now follows the platform branches, inside the existing non-WASM guard. |
| `gpu_runtime.c`, finalization and host-write cleanup | Share one owner-aware cleanup path. The review found a real resource bug: cleanup selected its SDK from the current environment rather than the device object's owner. Commit `fa945fb0` retains that owner in existing header space, resolves auto selection in one place, and removes the redundant raw release entry point and cleanup wrapper. |
| `http_chunked_tests.c` and `http_framing_tests.c`, refusal rows | Keep. These are input/expected-error permutations passed to existing shared assertion helpers, not repeated decoder implementations. |
| `gpu_metal_tests.m` and `gpu_opencl_tests.c`, dense-transfer cases | Keep. These pin each SDK's allocation, transfer and release calls independently. The input matrix is intentionally the same; combining the SDK fixtures would obscure which adapter is exercised. |
| `http_origin.c` and `http_tls_tests.c`, listener and request-reader fixtures | Keep. These are transport-bound test oracles with different socket/SSL calls and ownership. A generic callback transport solely to merge these two fixtures would hide the failure paths the tests expose. |
| `http_origin_tests.c` and `websocket_runtime_tests.c`, listener setup | Keep. The socket setup is similar, while the listener threads implement different refusal protocols and use distinct ports and client lifetimes. |

The additional numeric review leaves the host IEEE conversions and device implementations independent: `gpu_float_tests.c` uses the host implementation as an oracle. Merging those implementations would make their differential comparison tautological. Binary32 and binary64 host matrix products already share `PRODUCT`; device products share `MATRIX_KERNEL`; the integer-width rows share their checked-operation template. Tensor list and dense-buffer loading already share the parser and chunk reader in `tensor_file.c`, and the tensor reader already uses the host binary16 widening helper. None of those shared algorithms is copied into a new implementation.

For process waiting, `runtime-dup-review/process-pair.json` records both original definitions and their matching canonical hashes. `process-merge.json` records the shared definition's matching hash. The native process suite passes before and after the move, retaining its real subprocess, callback, failed-allocation, descriptor-exhaustion and unavailable-status checks. Both Osprey flavors also pass the unchanged asynchronous-process golden under GC and ARC, with warnings treated as errors and zero ARC live objects; redundant callback annotations were removed after the inferred versions produced the same output. Cross-flavor IR parity and `make lint` pass. The Windows body has identical statements and signature, but this local execution is POSIX; it is not a claim that Windows CI ran. The common definition remains excluded from WASM, and the WASM ARC archive rebuilds successfully.

The resident-resource regression fails before the ownership fix, then passes with both adapters compiled, Metal only, OpenCL only and neither. These are **mock adapter configurations**. They check uploaded inputs, resident outputs, host writes, repeated finalization and preservation of a pending I/O reason after selection changes to the host, an invalid name or the other adapter. The unchanged native 40-byte header and memory accounting assertions pass. Real Apple M4 Max execution separately passes all 6,775 device checks and both buffer flavors under GC and ARC, with 115 dispatches per run and zero ARC live objects; the two WASM ARC buffer goldens also pass. OpenCL hardware is not claimed.
