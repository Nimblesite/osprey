## Confirmed findings

1. **High severity · Android bank acceptance coverage regressed.** The release exercised deposits, withdrawals, transfers and refusals through native widgets against a live ledger and asserted the resulting balances. The candidate's required Android bank target boots the store, delivers one control event and accepts an increase in the frame revision. A broken Android transfer submission can pass that gate. The host-free banking tests cannot exercise the Android control binding. Restore an on-device multi-step journey with a balance and refusal assertion. [Release journey](https://github.com/Nimblesite/osprey/blob/71781d3a56c46e79e4c0da5b2f9fe41c61e081bd/src/osprey/examples/projects/modules/mobile/android/app/src/androidTest/java/org/ospreylang/talon/BankInstrumentedTest.kt#L45) · [Candidate gate](https://github.com/Nimblesite/osprey/blob/4bb4cfd8b39478a4a5cba79ab6d2d14f7f46fba0/src/toolchain/targets/android/tests/Makefile#L14) · [Pass condition](https://github.com/Nimblesite/osprey/blob/4bb4cfd8b39478a4a5cba79ab6d2d14f7f46fba0/src/toolchain/hosts/android/host/src/main/java/org/ospreylang/host/ViewCheck.kt#L43)
2. **High severity · DAW playback misreports success and failure.** This transport is new on the branch. Its final shell status came from stopping cache workers. With workers already finished, a successful render and device drain returned 1. With workers still running, a renderer failure or device failure each returned 0. All three cases reproduced using the candidate's actual shell command with controlled child processes. The fix in `b431cca9a` returned the expected status in all three cases and preserved the final clock receipt when the device acknowledged a frame after the renderer ended. These checks establish transport status handling. Audio underruns require separate measurement. [Reviewed transport](https://github.com/Nimblesite/osprey/blob/4bb4cfd8b39478a4a5cba79ab6d2d14f7f46fba0/src/osprey/examples/daw/src/daw_session.ospml#L175)
3. **Medium severity · CI lost Android lint coverage for the bank host.** The release ran lint for both Android projects. The candidate builds the shared bank host with `:host:assembleDebug` and runs `:app:lintDebug` only in the separate mobile example. A lint error specific to the new shared host can therefore escape this check. Run lint for the shared host in the required build. [Workflow](https://github.com/Nimblesite/osprey/blob/4bb4cfd8b39478a4a5cba79ab6d2d14f7f46fba0/.github/workflows/ci.yml#L1270) · [Host build](https://github.com/Nimblesite/osprey/blob/4bb4cfd8b39478a4a5cba79ab6d2d14f7f46fba0/src/toolchain/hosts/android/build.sh#L41)

## Other checks and limits

The runtime reviewer examined list allocation and ARC registry changes. I traced the sole caller of registry removal through the drop worklist. It obtains the slot just before removal and never dereferences it afterwards. We found no confirmed regression in this path. This was a source review, with no runtime memory-safety certification. [Removal caller](https://github.com/Nimblesite/osprey/blob/4bb4cfd8b39478a4a5cba79ab6d2d14f7f46fba0/src/toolchain/compiler/runtime/memory_arc_drop.h#L16)

The workflow review included the required CI, GPUI and WinUI definitions. The coverage-threshold file was identical at both endpoints. The Android findings were verified by following both Makefile recipes and the host scripts. Full-platform CI, the remaining files in the release diff and later commits fall outside these verdicts.
