# Implementation Plans — Unfinished Compiler Features

Each plan tracks unfinished compiler work. A plan is **retired** (struck
through, file deleted) once every checklist item is complete and named tests
prove it; any remaining work moves to a successor plan or a spec's §Status.
Plans are ordered by dependency impact and scope. Each plan ends with a TODO
checklist and records remaining work with concrete repros.

| ~~0002~~ | Generic functions & lambdas as values | codegen | **Done — plan retired.** Slot-driven specialization, let-alias and the emit-once cache landed earlier; the last four items closed together. A function value returning a TAGGED COLLECTION kept no element type — the lowered `FnSig` had no return-owner slot, so `|| => [0.5, 1.25]` was rejected with `match arms disagree on type`, a diagnostic naming no user construct; `FnSig` and `FiberSig` now CARRY the owner instead of each consumer rebuilding it, which is what left closure captures, function-value parameters and generic HOFs binding `None`. A still-generic **returned** lambda is materialised by inlining it at each call site of the binding (`let f = pick()` serves `f(7)`, `f("os")`, `f(2.5)`), with the producing call's arguments evaluated ONCE and carried in `Codegen::lambda_prefix` so effects are not duplicated per instantiation. The block-bodied-kernel and recursive-generic items were **stale** — both verified against the parent commit — and are now pinned by tests, and the annotations they had made load-bearing on `stress`/`mlkernels` are dropped, byte-exact. The one remaining refusal is a permanent restriction, not a gap: a still-generic lambda used as a bare value has no call site to specialise against, and is documented in [spec 0004](../specs/0004-TypeSystem.md) `[TYPE-GENERICS-FN]` and pinned by `a_still_generic_lambda_with_no_slot_at_all_is_rejected` | — |
