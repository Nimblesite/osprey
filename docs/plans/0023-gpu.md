# Plan 0023 — GPU computation and graphics backends

Contract: [0034 — GPU computation](../specs/runtime/0034-GPUComputation.md) · [0037 — arithmetic effects](../specs/language/0037-ArithmeticEffects.md) · [graphics README](../../examples/graphics/README.md) (graphics contract until a spec lands)
Depends on: [0037-osprey-native](0037-osprey-native.md) (WinUI host for the graphics-scene window)

## Prerequisites in place

- Metal and OpenCL execute admitted kernels and `gpuMatMul` via the shared device dialect (`compiler/runtime/gpu_f64.metal`, `gpu_math64.metal`, `gpu_math_ext.metal`, `gpu_device_lib.metal`) and dispatch contract (`compiler/runtime/gpu_device.h`); buffers stay device-resident between launches ([GPU-BACKEND-DEVICE], [GPU-BUFFER-RESIDENT]).
- `gpuScan` and `gpuFilter` have no device form and decline as a whole (`crates/osprey-codegen/src/gpu.rs`).
- GPT-2 generation and training run every kernel and product on the selected device (`GPU=auto`, `examples/gpt2/model/backends.osp`); `GPU=host` is the oracle. Half A is done; the 2× native-reference gate (Half B) is not.
- `examples/graphics/`: Metal renders on macOS; the D3D12 bridge draws every scene in software (WARP) only — no hardware adapter, and the Win32 window path (`ospgfx_d3d12_window.c`) still ships.

## Stage 4 — device coverage gates

- [ ] `gpuScan` device form [GPU-SCAN]: emit the sequential scan as the fold shape in `crates/osprey-codegen/src/gpu_device/` and drop the `declined(cg, "gpuScan has no device form yet")` call in `crates/osprey-codegen/src/gpu.rs`; acceptance: `crates/osprey-cli/tests/cross_flavor_ir_equiv/device.rs` shows a `osprey_gpu_launch` for `gpuScan` instead of a decline, host goldens unchanged.
- [ ] `gpuFilter` device form [GPU-FILTER]: stream compaction needs a kept-count channel in `compiler/runtime/gpu_device.h` (`OspreyGpuDispatch`); drop the `gpuFilter has no device form yet` decline; same acceptance as `gpuScan`.
- [ ] Preserve recovering `Arith` policies in selected-device regions [ARITH-DEVICE-RECOVERY]: integer-overflow probes under a wrapping handler recover on the host but abort on Metal/OpenCL; keep the no-trap contract and the fault tests in `compiler/runtime/gpu_device_tests.c`.
- [ ] Transcendental determinism decision [FLOAT-IEEE-RESULTS]: evaluate one shared host/device `exp`/`ln`/`tanh`, measure its CPU cost and verify exact cross-platform results before claiming them; the sampled tolerances in `compiler/runtime/gpu_shader_tests.c` prove no universal correct rounding.
- [ ] Kernel-to-kernel fusion and capability negotiation beyond the two adapters ([GPU-BACKEND-HOST] fusion gap; [GPU-BACKEND-PORTABILITY] explicit negotiation).
- [ ] Vendor-neutral substrate checkpoint [GPU-BACKEND-PORTABILITY]: record the shared device representation and launch/transfer interface for Metal, SPIR-V and WebGPU (optional CUDA must not determine the common ABI or require CUDA tooling), with benchmark evidence.
- [ ] CI with and without GPUs: adapter code compiles on its platforms; hardware lanes verify completed device dispatch and host parity on Apple, AMD, Intel, NVIDIA. A CUDA-only lane cannot close portable GPU delivery.
- [ ] Benchmark gate: within 2× of a native reference on the same GPU at matching precision for stencil + reduction micro-benchmarks AND GPT-2 Half B before the device flag is promoted; record numbers in `benchmarks/`.
- [ ] GPT-2 Half B: unchanged `examples/gpt2/` source against a native reference on the same GPU at matching precision within 2×; CUDA is the NVIDIA comparison only; record completed device commands and prove execution without CUDA on a non-NVIDIA GPU.

## Stage 5 — effect-selected execution

- [ ] Lexical adapter selection [GPU-DEVICE]: a handler-scoped adapter selector to replace the `OSPREY_GPU` environment bootstrap; unknown selections already fail in `compiler/runtime/gpu_selection_tests.c::invalid_case`.
- [ ] Design review against Xie et al. (ICFP 2024) handler-commutation results before any device interpretation reorders operations.

## Stage 6 — backend coverage and graphics convergence

- [ ] Multi-dimensional index spaces (rank-2/rank-3) shared by the device adapters: design the surface against `examples/gpt2/model/model.osp` attention and LayerNorm; land a `build2`/`get2` pair with declared shapes in the `Tensor<B>` effect so both interpretations get the rank at once ([GPU-BUFFER] rank-1 limit; [GPU-MATMUL] shape arguments).
- [ ] SPIR-V compute coverage for AMD, Intel and NVIDIA without CUDA: unchanged-source GPT-2 and the differential device gates [GPU-BACKEND-PORTABILITY].
- [ ] WebGPU/WGSL backend paired with wasm32 [GPU-BACKEND-PORTABILITY]; WGSL and SPIR-V are one device sublanguage with two spellings (LLVM SPIR-V backend is an official target).
- [ ] Optional CUDA interop through the shared backend contract; test that removing CUDA leaves non-CUDA GPU execution available.
- [ ] Extend the differential harness (`crates/run_test_corpus.sh`) so every backend must match the host goldens byte-for-byte.
- [ ] Metal kernel and graphics coverage in macOS CI: compute kernels already reach Metal via `crates/osprey-codegen/src/gpu_device.rs`; graphics convergence must reuse that path and the uniform ABI `examples/graphics/ospgfx_abi.h`.
- [ ] Graphics convergence: device shader emitter over the extracted-kernel ABI [GPU-KERNEL-EXTRACT], MSL first, `ospgfx_abi.h` slot protocol as the uniform binding; one scene's fragment body written as an Osprey kernel renders a frame byte-identical to the hand-written shader at matched uniforms; `base.metal` becomes generated output (hand-written library kept as the differential reference).
- [ ] GFX spec, owed when convergence lands: `[GFX-ABI]`, `[GFX-SHADER-LIB]`, `[GFX-UNIFORMS]`, `[GFX-HOST-PORTABLE]` in a new `docs/specs/` entry, each referenced from the implementing code.

## Stage 7 — autodiff and schedules

## Constraints

- No signed 64-bit division on a device: divide unsigned magnitudes only; never use a Metal device across `fork` (test aborts with mock adapters).
- A kernel's captures decide its device form: pass buffers and scalars, and read the recorded reason when a device run aborts.
- A new combinator sits on the existing chassis (`kernel_of`, `map_into`, `reduction`, `kernel_loop`); the element rule is `gpu::is_scalar` (`crates/osprey-codegen/src/gpu.rs`) — do not restate its match.
- `gpu.rs` and `gpu_kernel.rs` are near the 500-LOC cap: the next addition goes in a new module beside `crates/osprey-codegen/src/gpu/buffer.rs`.
- `GOLDEN_MIN` counts programs (not cases); `GPU_MODE_MIN` counts the `tests/core/gpu` programs re-run under the opposite lowering; both live in `crates/run_test_corpus.sh` and are never lowered.
- A new kernel lowering must be cache-keyed (`test_cache_key` in `crates/osprey-cli/src/executable_cache.rs` hashes `OSPREY_GPU_KERNELS`).
- Twins must emit identical IR; goldens are byte-exact under GC/ARC and wasm32 (`make -C website wasm` builds the wasm runtime archive — run both).
- Graphics invariant: `base/base.osp` and every `scene.osp` stay byte-identical across backends; `ospgfx_abi.h`'s static-inline helpers must be included with `-I`, never pasted; the bridge stays `-Wall -Werror`; `make -C apps graphics` on Windows needs the MSYS2 UCRT64 shell.
