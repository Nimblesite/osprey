## Flavor conversion — spec 0023, "Converting Between Flavors"

`AGENTS.md` stabilization mode bans new features, so this section does not start until the user lifts that ban for it. `[FLAVOR-BOUNDARY]` and `[FLAVOR-IR-EQUIV]` already give one `osprey_ast::Program` per flavor; the converter is the reverse arrow, a printer from `Program` to each flavor's text, guarded by parsing its output back. The rules below replace that spec section.

- **[FLAVOR-CONVERT]** Conversion succeeds only when the output, parsed in the target flavor, equals the input `Program` without positions (`osprey_ast::canonical::without_positions`, the comparison `cross_flavor_equiv.rs` makes) once generated names are normalized. Any mismatch is a `ConvertError` naming the first differing node and its position, and nothing is written. Curried stays curried and flat stays flat, so types and callers in other files are unchanged.
- **[FLAVOR-CONVERT-PRINT]** `osprey-fmt/src/print/` holds `mod.rs` (`convert(src, from, to)` and the guard), a `precedence.rs` shared by the three printers, and `default.rs`, `ml.rs` and `python.rs`, each under 500 lines. Printers emit raw text and `format_source(to)` lays it out; a desugared node prints in its canonical form when the target has no sugar that parses back to it, so output is correct where it is not idiomatic.
- **[FLAVOR-CONVERT-UNPRINTABLE]** A node the target flavor cannot spell (Python's rejected `return`, field and index assignment, augmented assignment, chained comparisons and typing forms; the ML-only stems in `cross_flavor_ir_equiv.rs`) returns `Unprintable { node, position, target, reason }` and is never approximated. The spec gains the printable-node matrix and a test proves every row.
- **[FLAVOR-CONVERT-TRIVIA]** `osprey_syntax::trivia(source, flavor)` collects `//` and `#` comments; the printer emits each before the first statement or arm after it, re-spelling the marker (`//` and `///`; `//` and `(** *)`; `#` and a `"""` docstring), and the guard checks the set of comment texts is unchanged. A comment inside an expression moves to the start of its statement, stated in the command's output.
- **[FLAVOR-CONVERT-FILES]** Default `.osp`, ML `.ospml`, Python `.py` with `# osprey: flavor=python` on line 1. The converted file is written beside the source and the source deleted, so `git` records a rename; an existing target path is refused before anything is written; converting to the file's own flavor reports "already <flavor>"; each `.expectedoutput` keeps its name.
- **[FLAVOR-CONVERT-FOLDER]** All or nothing: convert every opted-in source under the folder in memory (a `.py` counts only through its marker or `[project].python_sources`), report every `ConvertError`, otherwise write every file, update `osprey.toml` (`python_sources`, entry paths), type-check the rebuilt project graph once and restore every file on a failure there.
- **[FLAVOR-CONVERT-CLI]** `osprey convert --to <default|ml|python> [--check] <path>...`: `--check` runs the conversion and guard and writes nothing; otherwise it writes and prints `old -> new` per file. One commented `Makefile` target and its `make help` entry.
- **[FLAVOR-CONVERT-VSIX]** `osprey.convertFile` (editor title menu, explorer context menu for `.osp`, `.ospml` and opted-in `.py` files, and the command palette; a quick pick of the two other flavors; unsaved changes saved first; the new file opens in place of the old) and `osprey.convertFolder` (folder context menu; a modal confirmation naming the rename count and whether `osprey.toml` changes; a progress notification), in `src/toolchain/vscode-extension/package.json` and a new `client/src/convert-commands.ts`. Every `ConvertError` goes to Problems with its file and position, and the notification says nothing was written.

Tests, each written failing first: the corpus round trip in `osprey-fmt/tests/corpus.rs` converts every program under `src/osprey/tests/` and `src/osprey/examples/` in all six directions and asserts that the guard passes or the matrix's `Unprintable` returns, that comment texts are preserved and that the output is a fixed point of `format_source`; text is byte-identical after one Default → ML → Python → Default cycle; each converted corpus program passes `run_test_corpus.sh` under GC, ARC and wasm32 against its `.expectedoutput`, and `cross_flavor_ir_equiv.rs` gains converted twins with identical IR; `failscompilation/` sources report their parse errors; `osprey-cli/tests/` converts a copy of the graph in `mixed_flavor_project_graphs_emit_identical_ir` to each flavor and asserts the renames, the `osprey.toml` edits, the single type-check and identical IR, then that a planted unprintable node, a pre-existing target path and `--check` each write nothing; a VSIX `test/suite/` test drives both commands and asserts the new editor, the files on disk, the Problems entries for a failing folder, and that an untouched `.py` script stays a Python document.
