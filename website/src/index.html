01 / Three pillars

Safety. Elegance.
Performance.

Osprey exists to minimise bugs and failures, to express more program with less text, and to run natively. Every feature on this page serves one of the three.

Result

Safety

Algebraic, with no panics. Failures are Result values the caller must handle, matching is exhaustive, integer arithmetic follows a stated Arith policy, and effects make outside work visible and replaceable.

Read the effects contract ↗
{ λ }

Elegance

Inferred types, effects instead of plumbing, and no separate async form. Less text means fewer tokens: programs are cheaper for AI agents to read and write, and easier for people to hold in their heads.

Compare the syntax flavors ↗
LLVM

Performance

Native binaries through LLVM with no VM or JIT warm-up. Static handler selection removes runtime effect dispatch, fibers are lightweight, and the memory backend is a per-build choice.

See the benchmarks ↗

03 / Operations and handlers

Effects
with typed handlers.

effect declares an operation’s arguments and result type. perform requests the operation; a handler supplies the implementation.

Choose storage once: disk(onSave) supplies it for onSave and the saveDraft helper it calls. Neither function takes a storage object. Replace the handler in a test to simulate a failure; the application logic stays the same.

The compiler checks operation types and rejects requests without a matching handler, including requests made through helper functions.

See effect and handler syntax ↗

Osprey is actively evolving. Native control effects support single-shot resumption; full scoped effect rows and reusable continuations remain in development. Current support →

Three syntax flavors. One language.

A syntax flavor is a way to write the same Osprey language: Default uses braces, ML uses indentation, and Python flavor uses Python-style syntax. Choose per file and import across flavors; all share one type system, effects and compiler.

06 / Python flavor and tensor handlers

Port your Python.
Choose CPU or GPU handlers.

Keep def, lambda, and f-strings. Port computation into Osprey’s Python syntax flavor with inferred types and checked effects. Keep Python libraries through explicit interop.

GPT-2 is the worked port: one Tensor effect, a CPU handler, and a GPU handler using Metal or OpenCL. The handler decides where the arithmetic runs.
