# @osprey/synth

Pure synthesis components for Osprey, extracted from Prism. The library contains no UI or device playback code. Prism's editor and playback adapter remain in the example; Light Orchestra uses this package as a separate consumer.

The initial `synth::Voice` module supplies pitch conversion, periodic wave shapes, LFO rates, patch sampling and WAV encoding. `synth::Patch` is generated from [patch.td](patch.td). This initial renderer retains Prism's 11,025 Hz/8-bit preview behaviour and approximate filtering; it is not yet a real-time, bandlimited production engine.

The [library contract](../../../../docs/specs/runtime/Synthesis.md) defines modular typed graphs, routable/chained components, stateful audio processing, UI-independent Signals and future VST3 hosting. The [research collection](../../../../docs/research/synthesis/README.md) links fundamentals and modern papers to concrete experiments. These are delivery requirements; unimplemented features are marked as such.

Regenerate a model with the upstream typeDiagram emitter:

```sh
node scripts/make/osprey-schema.mjs /path/to/typediagram/dist src/osprey/packages/synth/patch.td src/osprey/packages/synth/src/model.ospml synth
```

`Graphs` validates typed ports and compiles a deterministic schedule, rejecting cycles without explicit delay. `Parameters` checks edits against descriptors and applied revisions; `Observations` reads component values through `Signal<Observation>` without a UI dependency. `Oscillators`, `Envelopes` and `Filters` provide explicit-state scalar reference processing. These record/list-based paths have **not** been verified as allocation-free audio callbacks.

Run `make -C src/osprey/packages synth` for the independent package journeys and the coverage gate; it then compiles every project built on synth (the daw, its test and render projects, the pocket orchestra kernel), so a synth change that breaks a consumer fails here [PKG-CONSUMERS-BUILD]. The suite covers routing, delay feedback, corrupt graph records, same-kind component Signals, stale edits, waveform/state continuity, ADSR and filter responses across sample rates. The current shared renderer is exercised by `make -C src/toolchain/targets/tests synth`, which drives Prism's complete editor and checks the samples and host playback requests.

`Components` supplies mono oscillator, filter, gain, mixer, delay and output nodes. `Renderer.start` validates/allocates an offline reference graph, `Renderer.block` carries state across blocks, and `Renderer.automated` applies ordered parameter changes at exact sample positions. `Renderer.observed` produces the next typed meter/parameter snapshot for Signal handlers. The current reference graph supports sine sources and mono routing; other oscillator shapes are available through `Oscillators` directly. For multichannel patches use `GraphClips`.

In Prism’s Add component picker, choose **Channel split** for a separate mono port per lane, **Channel join** to assemble them, or **Channel route** to reorder lanes. The default route swaps left and right. `Components.routeChannels(id, width, map)` takes one input index per output lane, with −1 for silence. **Mixer** combines two inputs of equal width, with independent linear gains from 0 to 1. **Panner** spreads one mono input across the prepared output order at equal power. Position −1 selects the first lane, +1 the last, and intermediate positions blend adjacent lanes. `Components.mix` and `Components.panner` accept widths from 1 to 64.

**Oscillator shapes and performance timbres** are implemented in [waves.ospml](src/waves.ospml). The production synthesis formulas live in eleven native Osprey modules. The [synthesis specification](../../../../docs/specs/runtime/Synthesis.md) lists the properties checked against production source, their assumptions and their references.

`Performance.wave` provides UI-free scalar Glass, Bass, additive Pulse and FM Orbit timbres, with harmonic tone and metallic ring-modulation controls. Light Orchestra calls it from its producer thread and keeps delay storage and audio devices in its host. Echo and Schroeder-style reverb currently belong to that host adapter. They are pending extraction into reusable graph processors. Oversampling and measured alias rejection remain outstanding.

## Formula melodies [SYNTH-FORMULA-NOTES]

A formula melody turns a typed formula into MIDI notes. The formula is evaluated once per step with `t` set to the step number, and each value becomes one note: `60 + t * 7 % 12` climbs in fifths folded into the octave above middle C. `Components.formulaMelody(identity, formula)` builds a 16-step note source. Wire it to a MIDI oscillator's event inlet like the MIDI note component. `Formulas.parse` reads `+ - * / % ^`, parentheses, `t`, decimal numbers and `sin cos abs floor round sqrt`; it reports the column of the first thing it cannot read. A step with no finite value is a rest, and pitches outside 0–127 are moved by whole octaves into range. In Prism, choose **Add component → Formula melody** and type into **Formula over step t**. The [synthesis specification](../../../../docs/specs/runtime/Synthesis.md#formula-melodies-synth-formula-notes) defines the language and timing exactly.

## Granular reference engine [SYNTH-ADVANCED-GRAINS-PLAYBACK]

`Grains.prepare(source, capacity)` accepts 2–1,048,576 finite mono samples in [-1, 1] and a pool capacity of 1–256. `Grains.trigger(pool, controls)` returns a `GrainAdmission` receipt containing `pool` and `accepted`; callers must retain its returned pool. Capacity available means `accepted=true` and a new grain at the current sample position. A full pool returns `accepted=false`, increments the rejected-request count and preserves every existing voice. This explicit reject-new policy keeps scheduled playback advancing instead of failing the block. Active identities are monotonic, unique and never reused within a pool.

`GrainControls` is generated from [grains.td](grains.td):

| Control | Unit and accepted range | Behaviour |
| --- | --- | --- |
| `window` | `HannWindow` or `AsrWindow(attack, release)` | Shape is retained for the grain lifetime |
| `start` | Source samples, 0 inclusive to source length exclusive | Fractional initial source position |
| `rate` | Source samples per output sample, -16 to 16 | Negative reverses; zero holds a position |
| `duration` | Output samples, 3–65,536 | Lifetime is independent of rate |
| `amplitude` | Linear gain, 0–1 | Multiplies the grain window |
| `pan` | -1 to 1 | Equal-power placement from left to right |

`Grains.next(pool)` returns a stereo sample and next state. `Grains.block(pool, frames)` returns 1–2,048 stereo frames and next state; cursors and lifetimes carry across calls. The source wraps periodically, including interpolation from its last sample to its first. Both Hann and linear ASR windows have explicit zero endpoints. ASR attack and release are positive fractions of `duration - 1` whose sum cannot exceed one; the remainder is sustain. With very short grains, discrete sampling may miss a narrow peak. Graph parameters `window` (0 Hann, 1 ASR), `attack` and `release` affect newly triggered grains only; unsupported selectors and invalid ASR fractions return errors. Linear interpolation is **not bandlimited**; pitch changes can alias. The caller supplies rate conversion when source and output sample rates differ. Stereo files use a mono downmix.

`Grains.withRegion(pool, region)` selects the absolute, half-open source frame range `[first, limit)` for future triggers. The default covers the entire source. `LoopSource` interpolates the last frame toward the first and wraps in either direction. `OneShotSource` holds the final interpolation tap on the last frame and ends the voice when its cursor exits the region. At zero rate the grain holds its position until its window ends. Changing the region leaves active voices on their original range and boundary policy.

`GrainCapture.prepare(capacity, sampleRate)` creates a bounded mono capture. Call `write` with 1–2,048 finite normalised samples per block. It keeps the newest `capacity` frames (2–1,048,576) and counts all accepted frames. After at least two frames, `freeze` creates an immutable snapshot. `resource` prepares it with a name and MIDI root for the same granular factory that accepts a WAV. `thaw` continues from the same write position. This allocating reference path runs outside the device callback.

Call `Grains.replaceSource(pool, samples)` between render blocks to change the mono source. Active grains finish on the previous buffer. New triggers use the replacement immediately and address its full length with the current boundary policy. The pool releases the previous buffer after its last voice finishes and rejects a second replacement while that buffer still has voices. A failed replacement preserves the pool, clock and admission counts.

Overlapping grains sum without clipping or automatic loudness compensation. Up to `capacity` unity-gain grains can sum constructively; reserve output headroom or use a downstream gain/limiter. The pool rejects new grains on exhaustion rather than stealing an audible grain. Invalid controls, malformed active voices and exhausted counters return errors. Preparation validates the complete source; playback checks samples as they are read.

`Grains.observation(pool)` exposes current and retiring source lengths, the selected region, bounded per-voice cursor/age/region snapshots, request revision, rendered sample position, active count, capacity, requested/accepted/rejected/stolen counts and lifetime-average requested/accepted events per rendered frame. Multiply these densities by the output sample rate for grains/second. At position zero both densities are zero because no duration has elapsed; counts still report requests. Stolen count is always zero under reject-new. A host publishes this snapshot through its handler for `Signal<GrainObservation>`; `Grains.observe()` reads that effect without importing UI code. Revision advances on every valid request, including capacity rejection; accepted count and stable IDs advance only when a voice starts. Invalid requests return errors and leave all counts unchanged. Sample position advances on rendering. Publication and subscriber scheduling belong outside the audio callback.

The allocating reference engine is covered by the synth package journeys. Device callback performance, sustained playback and native control verification are tracked in the [advanced synthesis plan](../../../../docs/plans/advanced-synthesis.md).

`PitchMarks.prepare(position)` starts a separate causal scheduler for a clean bipolar reference with one upward zero crossing per fundamental period. Feed `PitchMarks.block` 1–2,048 reference samples at the output rate. It marks the first nonnegative sample after a negative one, including across blocks. It needs no lookahead and quantises the crossing to the next sample. It begins marking after the first negative sample. Feed the absolute positions to `GrainScheduler.events` or `GrainDistributions.events`. The reference must supply its fundamental explicitly or have one upward crossing per period. Harmonics, noise and DC offsets can create extra or missing marks. This mode does not estimate fundamental frequency from arbitrary recordings.

For an editable starting patch, use `Patches.grainCloud()` for scattered grains, `Patches.rhythmicGrains()` for a 25 Hz pulse through a resonator, or `Patches.frozenTexture()` for overlapping grains from a frozen A1 capture. Each returns a checked graph with a fixed seed and an LFO cable. Follow the cable to adjust level motion in the cloud and frozen patches or cutoff motion in the rhythmic patch. Render at 48 kHz with `GraphClips.start`, then pass the returned state to `GraphClips.next`.

### Sample-timed grain scheduling [SYNTH-ADVANCED-GRAINS-SCHEDULING]

`GrainScheduler.prepare(position, timing, seed)` creates an independent onset clock. `PeriodicTiming(period, jitter)` retains periodic/jittered scheduling: `period` is 1–1,048,576 output samples, `jitter` is 0 up to `period - 1`, and `seed` is 1–2,147,483,646. The first onset is at `position`. Zero jitter gives a strictly periodic stream; positive jitter varies each following interval within `[period - jitter, period + jitter]`, with at least one sample between onsets. `ExponentialTiming(mean, maximum)` selects asynchronous gaps: `ceil(-mean * ln(1 - seed / 2147483647))`, clamped to `[1, maximum]`. Mean is finite in [1, 1048576] and maximum is an integer in [1, 1048576]. Rounding and capping change the realized mean and create mass at the cap; this is a bounded renewal process, not an exact Poisson process or pitch-synchronous analysis. The configured mean is the underlying exponential scale, not a promise of measured density.

`GrainScheduler.block(clock, frames)` emits absolute positions in `[clock.position, clock.position + frames)` and the next clock, for 1–2,048 frames. An onset exactly at the block end belongs to the next block. The next onset and random state persist across calls, so changing block lengths does not restart either. The generator uses the recurrence `seed = (48271 * seed) mod 2147483647`; each onset advances it once, including when jitter is zero. Mapping its finite state space into interval bins has finite discrete bias; this is not a cryptographic generator. Recreate the clock with the same initial seed to reset the sequence, or a different seed to start another sequence. Parameter edits to an existing clock affect intervals computed after its already scheduled next onset.

`GrainScheduler.events(positions, controls)` maps onsets to `GrainEvent` values. Callers can instead construct events with independently varied source position, rate, duration, amplitude and pan. `Grains.scheduled(pool, frames, events)` applies them **before** rendering their exact sample. Events must be sorted by absolute position, belong to the current half-open block interval, and number at most 2,048. Equal-position events preserve their input order; stale, unsorted and next-block events are rejected rather than silently discarded. `Grains.block` uses this same render path with no events.

When connecting scheduler and player, start them at the same sample position. Retain both returned states only after rendering succeeds; capacity rejection consumes the scheduled event and updates observations while existing grains finish their envelopes. Malformed events or exhausted counters return errors with no partial state to publish. Save the entire clock, including `nextOnset` and the current seed, to resume a patch. These implementations have passed static checking; partition-equivalence and audible scheduling verification remain deferred with automated testing paused.

`GrainClouds.prepare(source, capacity, timing, seed, variationSeed)` composes both primitives at sample zero. `GrainClouds.block(cloud, controls, frames)` checks clock alignment and returns stereo buffers plus one combined next state only when scheduling and playback both succeed. New controls affect newly triggered grains; existing grains retain their controls. A block with no onsets does not apply the supplied controls. `GrainClouds.observation` combines playback activity with the applied timing policy and the next onset, and `GrainClouds.observe` reads its UI-independent Signal. This convenience composition uses the same player/timeline path; it introduces no alternate DSP algorithm.

### Granular graph module [SYNTH-ADVANCED-GRAINS-INTEGRATION]

`Components.granular(identity, resource, capacity, seed)` creates a stereo source node with checked sample metadata/data and twenty-one parameter descriptors: `start`, `rate`, `duration`, `gain`, `pan`, `period`, `jitter`, `window`, `attack`, `release`, `timing`, `maximumGap`, `positionSpread`, `rateSpread`, `durationSpread`, `gainSpread`, `panSpread` `variationSeed`, `regionStart`, `regionEnd` and `boundary`. Region bounds use whole source frames and exclude the end. Boundary 0 loops and 1 plays once. A saved node without any region descriptors keeps the original full-source loop. Timing selects 0 for periodic jitter or 1 for bounded exponential; `period` supplies the integer mean in exponential mode and `maximumGap` caps its gaps. `jitter` affects only periodic mode. `GraphClips` stores typed per-node memory: independent scalar-channel states or one stereo grain-cloud state. The cloud uses `GrainGraph` to decode exact integer timing fields and interleave the same `GrainClouds` output. Its source memory, capacity and sample clock are checked when continuing a graph. A downstream external-node suspension retains already-rendered cloud memory at the end of the pending block; completing the worker response does not render the cloud twice.

The current graph/device rate is 48 kHz and the grain block limit is 2,048 frames. Source sample storage counts toward the graph's existing bounded storage budget. The library node accepts a prepared `SampleResource`, including resources decoded by `SampleResources.decodeWave`; Prism supplies the file chooser and uses MIDI 60 as the import root. Sample-source graph nodes, scheduler event ports and audio-rate modulation adapters remain planned. The node is available in Prism's module picker, with built-in source data and the existing parameter inspector; live graph edits still take effect on playback restart.

Block rendering validates pool and voice invariants once at entry, and uses a private loop that preserves them while consuming checked events. Public `next` and `trigger` calls retain their own validation; sample reads still reject nonfinite/out-of-range source data. Native grain audition has completed through the stereo device path, but the device reported empty-queue callbacks. Continuous throughput and exact output correctness remain unverified; the reduced validation work has no measured speedup claim yet.

### WAV import limits and tuning [SYNTH-ADVANCED-GRAINS-IMPORT]

`WaveImport.decode` accepts one complete little-endian RIFF/WAVE file of 12 bytes to 8 MiB, holding PCM 8, 16, 24 or 32-bit or IEEE float32 samples, mono or stereo, at 8–192 kHz, with 2 to 1,048,576 complete frames. Every other encoding, `WAVE_FORMAT_EXTENSIBLE`, three or more channels, a block alignment or byte rate that disagrees with the format, duplicate or truncated chunks, more than 1,024 chunks, and float samples that are not finite or lie outside [-1, 1] are refused with a message. Unknown chunks are skipped, and odd-length chunks are read with their padding byte. The resource retains both original sample words in each stereo frame. Grain Cloud prepares its mono source with `(left + right) / 2` (`WaveMath.mono`). Swapping the channels changes the resource identity. Nothing is resampled. The resource keeps its own rate, and `SampleResources.playbackRate` sets the grain rate to `(source rate / output rate) · (note frequency / root frequency)`. Prism imports every WAV with root MIDI 60 (C4), so C4 plays the file at its recorded pitch, C5 at twice its speed, and a note that needs a rate above 16 is refused. The scan position (`start`, region bounds and spread) is never changed by pitch. Grains read the source with linear interpolation, which is not bandlimited, so large upward transpositions can alias. Prism replaces a sample only while playback is stopped. Choosing a sample during playback is refused with a message, and Undo and Redo restore the previous resource whole.

### Independent grain variation [SYNTH-ADVANCED-GRAINS-DISTRIBUTIONS]

`GrainDistribution(minimum, maximum)` contains two valid `GrainControls` records with ordered bounds and the same window. `GrainSeeds` retains separate Park–Miller states for position, rate, duration, amplitude and pan. Each seed must be in [1, 2147483646]; use distinct seeds to avoid deliberately identical streams. These are reproducible streams, not a claim of statistical independence or cryptographic randomness.

`GrainDistributions.events(positions, ranges, sourceSize, seeds)` returns up to 2048 ordered events and the next seeds. It draws continuous uniform values for source position, playback rate, gain and pan, and inclusive discrete uniform duration. Fixed bounds still advance their stream once per onset. Empty batches advance no streams. Window settings remain fixed, and rate is a linear playback ratio rather than semitone-uniform pitch. Invalid bounds, seed states or ordering return errors. The finite generator gives quantisation bias.

`GrainClouds.variedBlock(cloud, ranges, frames)` composes the existing onset clock, distribution generator and grain player; retain `result.next` only after success. The cloud owns both the onset clock and all five parameter seeds. Overloaded/rejected onsets still consume their parameter draws, so pool capacity does not alter future random choices. Invalid rendering returns no partial clock or seed state. This library API is implemented and strictly compiled; Native inspection of distribution controls, rendered replay/partition evidence and statistical checks remain pending.

`GrainSpreads.around(controls, sourceSize, spread)` builds ordered variation bounds from symmetric widths, clipped to the graph domains: source position [0, sourceSize−1], rate [−16, 16], duration [3, 65536], gain [0, 1] and pan [−1, 1]. Width zero holds the parameter. The graph uses `variedBlock` for all grain rendering, including zero-spread patches; each scheduled request advances all parameter streams even if capacity rejects it. `variationSeed` is a restart-only initializer, distinct from the onset seed. `GrainDistributions.seeded` derives initial states with documented fixed offsets (0, 104729, 130363, 155921, 196613) modulo the valid seed domain; it does not promise statistical independence. Changing spreads does not reseed. Constant-control `GrainClouds.block` retains parameter seeds unchanged because it requests no variations.

### MIDI oscillator release [SYNTH-HOST-MIDI-OSCILLATOR-RELEASE]

A MIDI-connected oscillator releases with a fixed 240-frame (5 ms at 48 kHz) linear envelope; there is no public per-voice duration control yet. Matching note-off or zero-velocity note-on starts the envelope, with full velocity at its first sample and exact zero at its last. Phase and release progress persist across blocks. Prism currently applies edits after playback restart. Idle voices retain their phase without advancing it. Repeated note-offs do not restart a tail, and unrelated identities do not affect it. A positive-velocity note-on cancels the tail and takes ownership without resetting phase. There is no attack envelope, voice crossfade, polyphony or live topology migration yet; this does not establish click-free realtime behaviour. Unwired oscillators retain frequency-controlled free running. Strict compilation passed; audio verification remains pending.


### Offline fit provenance [SYNTH-ADVANCED-LEARNED]

`FitReports.fit(graph, config, training, evaluation)` uses the package’s log-spectrum fitter on the training clip. Supply two normalised, mono 48 kHz references of a supported FFT length. Each reference carries a source identifier and licence. The wrapper rejects identical identifiers or identical sample arrays. The caller supplies genuinely independent recordings or disjoint excerpts.

The report carries the method identifier, implementation licence, both source records, search configuration (including seed and bounds), fitted values, training loss history and a separate evaluation loss. Evaluation scores the selected values once and never influences the search. The original graph remains available. Use the fitter’s explicit apply operation to adopt the values.

## Advanced synthesis families [SYNTH-ADVANCED]

Every family below is a set of independent, UI-free modules: models are declared in typeDiagram (`physical.td`, `tables.td`, `spectral.td`, `phase.td`, `fitting.td`), formulas live in native Osprey (`PhysicalMath`, `TableMath`, `SpectralMath`, `NonlinearMath`, `PhaseMath`, `FitMath`), and each module has `configure` (typed rejection of invalid controls), `initial` (explicit state) and `next` (one sample). Graph nodes wrap the same modules; the graph runs at 48 kHz and all storage counts against its 1,920,000-sample budget. These are allocating list-based **reference** implementations: nothing here is verified realtime, and spectral and reverb nodes cost milliseconds per sample in the graph renderer. Automated test suites are paused; the evidence quoted is from scratch measurement programs and is recorded in the [plan](../../../../docs/plans/advanced-synthesis.md).

| Node (`Components`) | Ports | Controls (units) | Latency / state |
| --- | --- | --- | --- |
| `exciter` | → audio | strength (linear 0–1), duration (1–48,000 frames), interval (frames, 0 once), excitation (0 impulse, 1 seeded noise), colour (0 white–1 dark) | Park–Miller seed fixed at preparation |
| `resonator` | audio → audio | frequency (Hz < 0.45 fs), decay (T60 s), gain, response (0 band-pass peak, 1 struck) | two-pole state; edits keep stored energy |
| `modalBank` | audio → audio | body (0 string, 1 bar, 2 membrane, 3 bell), modes (1–8), fundamental (Hz), decay (T60), brightness, strike (0.01–0.99) | 8 slots; modes ≥ 0.45 fs silent; idealised ratios |
| `waveguide` | audio → audio | pitch (20 Hz–0.45 fs), decay (T60), brightness, dispersion (allpass −0.95–0.95), pickup (0–0.5) | capacity bounds the lowest pitch |
| `fractionalDelay`, `lossFilter`, `allpass` | audio → audio | delay (samples), loss gain ≤ 1 and brightness, allpass coefficient | linear interpolation is not bandlimited |
| `wavetable` | → audio | pitch (Hz, negative reverses), position (0–1 morph), level | octave mip levels, exactly bandlimited per level |
| `additive` | → audio | pitch, partials (0–64, fractional fades), tilt, odd/even, decay, damping, inharmonicity B, stretch, retrigger interval | peak-safe sum; partials fade between 0.4 and 0.45 fs |
| `spectral` | audio, optional side → audio | transform (0 pass, 1 freeze, 2 band, 3 shift, 4 smear, 5 morph), hold, low/high (Hz), shift (bins), amount, mix | latency size − 1; dry path aligned |
| `shaper` | audio → audio | curve (tanh, hard, cubic, fold), drive, bias, level, ADAA, 2× oversampling | ADAA ½ sample; oversampling 15 samples |
| `reverb` | audio → audio | size, decay (T60), damping, diffusion, mix, freeze | Householder FDN; freeze is lossless with muted input |
| `shifter` | audio → audio | shift (±5 kHz), ring, mix | Hilbert pair ~20 Hz–0.47 fs |
| `phaseOperator` | optional modulation, sync → audio | frequency, shape (plain, PD, windowed PM, WPPM), breakpoint d, two pulse index/ratio/offset sets, PM depth (cycles), FM spread (Hz), feedback, level | not antialiased |

Sources: Smith, *Physical Audio Signal Processing* (waveguides, loss filters, pick-position combs, allpass dispersion); textbook modal ratios (approximations, not instrument measurements); Fletcher's stiff-string inharmonicity; Allen–Rabiner overlap-add with periodic Hann windows; Parker, Zavalishin and Le Bivic, DAFx 2016 (first-order ADAA); Niemitalo's polyphase Hilbert coefficients; and M. Smart, *Wave Pulse Phase Modulation*, DAFx25, equations (1) and (3)–(9), transcribed exactly in `phase_math.ospml`.

`Fitting` searches chosen automatable parameters offline: it renders candidates through the production `Graphs`/`Renderer` path, scores Hann-windowed log power spectra against a power-of-two target, explores uniformly for a quarter of the budget and then refines with a (1+1)-ES. It is deterministic for a seed, bounded to 16 parameters and 10,000 evaluations, and `start`/`advance` expose single evaluations for progress and cancellation. `apply` returns a separate revalidated graph; the original is never modified. `Patches` builds reproducible example graphs for every family, including a seeded grain cloud exciting a modal body, followed by spectral processing, waveshaping, LFO-controlled gain and reverb (that one needs `GraphClips`, because the mono reference `Renderer` rejects control ports).
