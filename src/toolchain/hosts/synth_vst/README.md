# Prism VST3 worker [SYNTH-HOST-VST]

This process loads third-party VST3 modules separately from the Osprey application. It currently scans component IDs and runs a bounded offline lifecycle probe: initialize, activate audio/event buses, prepare 48 kHz float32 processing, send MIDI note-on/off events or an audio impulse, process 51,200 frames, deactivate and unload. Failed loads, absent class IDs, unsupported layouts and non-finite audio fail explicitly. This is a hosting foundation, not yet a streaming graph adapter or a sandbox.

Run `make -C src/toolchain/targets/tests synth-vst` from the repository. It fetches the pinned official SDK into `target/vst3sdk`, builds the worker and ADelay/mda fixtures into `target/vst-worker`, runs the SDK validator when building those fixtures, then runs eight process-level checks. It does not install plug-ins into the user's library and needs no audio device or window. Fetch/build/test commands have bounded timeouts.

The SDK is pinned to `3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96`; its exact submodule commits are supplied by that revision. The SDK and examples retain their upstream notices and [MIT license](https://github.com/steinbergmedia/vst3sdk/blob/3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96/LICENSE.txt). No SDK sources are copied into the repository.

`scan <module.vst3>` emits one JSON class record per audio component. `probe <module.vst3> <class-id>` is a test operation that requires measurable audio and emits peak/latency evidence. It intentionally rejects a silent plug-in result and is not a general playback API. The upcoming streaming protocol must distinguish a valid silent instrument from a failed processor.

Verified on macOS arm64 with ADelay and mda JX10. Windows and Linux loader paths are configured but not yet verified. The state probe changes a real processor parameter, verifies its saved bytes change, restores the original component state, flushes deferred state at a processing boundary and checks the controller value agrees. Automation is submitted at offset 17; this test does not establish that every plug-in honours that offset sample-accurately. Live restart notifications, streaming audio transport, host UI integration, crash/hang recovery, sandbox capabilities and callback-allocation evidence remain pending. A separate process alone does not restrict a native plug-in's filesystem or network access.

## Persistent blocks [SYNTH-HOST-STREAM]

`osprey-vst-worker stream <plugin.vst3> <class-id>` keeps one plug-in instance alive until stdin closes. The initial 16-byte response is `OSV1` followed by little-endian unsigned 32-bit input channels, output channels and a MIDI-input flag. This first transport supports one audio output bus, at most one audio input bus and at most one event input bus; unsupported layouts fail explicitly. Processing is float32, 48 kHz, offline mode, with 1–256 frames per block. This is worker transport, not a realtime device engine or Prism integration.

Requests contain three little-endian unsigned 32-bit counts: frames, notes and parameter points. At most 128 notes and 128 parameter points follow. Each note contains five unsigned 32-bit fields (kind: 1 on/2 off, sample offset, MIDI pitch, MIDI channel, note identity) and one float32 velocity. Each parameter point contains an unsigned 32-bit parameter ID and offset followed by a float64 normalized value. Notes and parameter points must each be ordered by offset. Audio follows, interleaved float32 with the advertised input-channel count. The canonical application-side types are generated from `src/osprey/packages/synth/host.td`.

Each response contains unsigned 32-bit frame count and plug-in latency followed by interleaved float32 output. A response is flushed before reading another request. The worker retains DSP state and advances sample position across blocks. Values, counts, layouts, event fields and parameter identities are checked before processing; malformed/truncated input produces `vst.failure` on stderr and a nonzero exit. EOF between complete requests ends cleanly. Silence is valid output, unlike the separate lifecycle probe. Hosts must bound response reads and kill unresponsive/crashed workers; this transport does not sandbox third-party native code.

The compact fixed-format transport avoids a new runtime dependency in the native worker. tdbin was considered: the available typeDiagram tree has Rust/TypeScript codecs but no C++ codec. A generated tdbin bridge remains a future option; this version is explicitly identified by its magic and is not presented as tdbin.

The stream journey uses actual ADelay and mda JX10 binaries: exact delayed PCM crosses a block boundary, MIDI starts at sample 17, a held note remains audible, a matching note-off with an explicitly short release becomes silent, dense events are accepted up to the limit, and malformed counts/values/order/IDs are rejected. ADelay's example bypass has an upstream TODO, so the PCM oracle uses its documented minimum one-sample delay rather than assuming bypass works.

`describe <plugin.vst3> <class-id>` emits one checked JSON descriptor with class name, channel counts, MIDI input support and up to 1,024 normalized parameters. Metadata is read after processor/controller synchronization; invalid values or unsupported layouts fail before any descriptor is emitted. `Hosted.component` in `@osprey/synth` converts the typed descriptor into a checked graph node with actual channel types and independent parameter identities.

`stream-text` accepts the same request bytes as strict hexadecimal on stdin and emits the response bytes as hexadecimal on stdout. It exists for native capability transports whose slices carry UTF-8; it uses the identical processor and packet checks, not a second renderer. Input is capped at 1 MiB decoded and output audio at 65,536 channel samples. The entire response is emitted only after the bounded clip succeeds. The persistent binary `stream` mode remains available for a future realtime engine.
